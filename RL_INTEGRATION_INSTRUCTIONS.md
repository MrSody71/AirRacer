## Шаг 1. Плагины

Вариант 1 (проще): заменить `AirRacer.uproject` на приложенный — плагин `NNERuntimeORT` уже включён.

Вариант 2 (через UI, если приложенный .uproject не подхватился): Edit → Plugins → в поиске набрать `NNE` или `ONNX` → включить **NNE Runtime ORT** (и **Neural Network Engine**, если показан отдельно) → перезапустить редактор.

`NNERuntimeORT` даёт и сам рантайм `NNERuntimeORTCpu`, и импортёр `.onnx`.

## Шаг 2. Импорт модели как ассета

1. В Content Browser создай папку **`Content/AI`** (путь в движке: `/Game/AI`).
2. Перетащи `Python/airracer_bot.onnx` в эту папку. Движок импортирует его как ассет **NNEModelData** с именем `airracer_bot`.
3. Проверь, что путь ассета — `/Game/AI/airracer_bot`. Если положишь в другое место/с другим именем — поправь `ModelAssetPath` в `AiBotController.h` (по умолчанию `"/Game/AI/airracer_bot.airracer_bot"`).

## Шаг 3. Замена файлов и сборка

1. Закрой редактор (Live Coding мешает внешней сборке — как у тебя в PROGRESS.md).
2. Замени 4 файла из таблицы выше.
3. Так как менялся `Build.cs`, пересобери проект (ПКМ по `.uproject` → Generate Visual Studio project files, затем Build в VS, либо `Build.bat`). Открой редактор.

## Шаг 4. Проверка

Запусти гонку (PLAY) и открой **Output Log** (Window → Output Log). Ищи строки `[AiBot]`:

- `NNE: модель загружена. Боты управляются обученной PPO-политикой` → всё работает, боты летят под нейросетью.
- `модель не найдена по пути ...` → не там/не так назван ассет (Шаг 2).
- `рантайм NNERuntimeORTCpu недоступен` → не включён плагин `NNERuntimeORT` (Шаг 1).

В любом из ошибочных случаев бот не падает, а просто продолжает лететь на rule-based — демо не ломается.

## Шаг 5. Тюнинг (если бот летит «зеркально»)

Модель обучалась в Python-симуляции на `scipy` (правосторонняя система координат), а UE — левосторонняя. Из-за этого возможна инверсия по одной оси: бот летит, но уходит от чекпоинта или кружит не в ту сторону. Это лечится переключателями на контроллере (`AiBotController`, секция `AI|NeuralNetwork`), без переписывания логики:

- кружит/поворачивает не туда по горизонтали → включить **bFlipYaw** (и/или **bFlipObsY**);
- крен в обратную сторону → **bFlipRoll**;
- пробуй комбинации, перезапуская гонку.

Эти флаги — `UPROPERTY`, поэтому их видно в défolt-свойствах класса/блюпринта; чтобы менять без пересборки, можно завести Blueprint-наследник `AiBotController` и переключать галочки там.

Если довести качество вождения за оставшееся время не выходит — оставь `bUseNeuralNetwork = true` там, где модель ведёт нормально, либо переключи на `false` (rule-based). В пояснительной записке мы в любом случае честно описываем **обе** ветки: rule-based как базовую линию и PPO-политику как обучаемого агента, со сравнением — это сильный материал для раздела «Тестирование».

## Шаг 6. Только для упакованного .exe (Shipping)

Модель грузится по строковому пути (`LoadObject`), поэтому для **упакованной** сборки её нужно явно включить в кук: Project Settings → Packaging → **Additional Asset Directories to Cook** → добавить `/Game/AI`. Для запуска в редакторе (PIE) этого не требуется.

## Как это соотносится с Вариантом 48

После Шагов 1–4 выполняется ключевое требование темы: «**C++ для интеграции с игровым движком**» — обученная в Python модель реально управляет агентами в игре через инференс на C++. Python тренирует → ONNX экспортирует → C++/NNE исполняет в движке.
